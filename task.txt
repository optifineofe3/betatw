Критический краш: приложение падает, если в чате есть хотя бы одно отредактированное сообщение.

Стек из tweak_debug.txt (можешь сам посмотреть):
SIGNAL 11 внутри
_logos_method$_ungrouped$WAMessageBubbleTableViewCell$layoutSubviews

Без EDITED сообщений всё работает. С EDITED — краш при layout ячейки.

### Что нужно сделать

1. Найди и устрани краш строго в пути isEdit внутри
   %hook WAMessageBubbleTableViewCell -layoutSubviews

2. Вероятные причины:
   - небезопасный performSelector / IMP-вызов для messageDate, latestEditTimestamp, lastEditTimestamp и похожих геттеров (могут возвращать примитив, а не объект)
   - тяжёлая/опасная работа с edit chain / original text прямо в layoutSubviews
   - обращение к nil объектам при сборке badgeData/chain только для edited сообщений

3. Требования к фиксу:
   - layoutSubviews должен быть максимально лёгким и безопасным
   - никакого тяжёлого record/persist chain на каждый layout
   - все обращения к свойствам WAMessage только через безопасные обёртки (проверка signature/return type + @try/@catch)
   - DEL не трогай
   - логику показа EDT/EDITED сохрани
   - multi-edit history не выкидывай, но тяжёлую запись истории убери из layout path (оставляй в edit hooks: attachMessageEdit / applyOutgoingEdit и т.п.)

4. После фикса:
   - чат с отредактированными сообщениями не должен крашиться
   - бейдж EDITED/EDT должен остаться
   - тап по бейджу и история правок должны работать

Сделай точечный профессиональный фикс, без большого рефакторинга всего твика.
